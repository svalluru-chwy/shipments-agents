Entry 1: Project Initialization and Architecture (2026-02-12)
-------------------------------------------------------------
WHAT: Created standalone shipments-agents platform from scratch.

WHY: Need a standalone shipments agency with local API capabilities,
     modeled after autoship-agency-platform. This decouples shipments
     analysis from the broader cat-agents monolith while keeping all
     17 shipment skills intact.

HOW: Analyzed 4 source repositories:
  - cat-data-operations: 28 Snowflake queries, 7 relevant to shipments
  - cat-agents: 17 shipment skills across 4 phases, skill loader infra
  - shipments-agency-streamlined-main: 7-step pipeline with validation
  - autoship-agency-platform: Template for standalone platform pattern

DECISIONS:
  1. 3-agent architecture (signals, decoder, actions) with internal
     phased skill execution (4 phases of 17 skills).
  2. Hybrid skill model: 11 deterministic Phase 1 skills for exact
     metrics + 6 LLM skills for reasoning/interpretation.
  3. No UI -- backend/API only.
  4. Exposed individual skill endpoints (/skills/{name}/run) and
     phase-level endpoints (/skills/phase/{n}/run) for debugging.
  5. Kept all conventions from autoship-agency-platform (BaseAgent,
     AgentInterface, AgentRegistry, PipelineOrchestrator, etc.).

Entry 12: Bug Fixes -- current_order + shipment_delay_predictor (2026-02-13)
------------------------------------------------------------------------------
WHAT: Fixed two skill bugs that were also broken in cat-agents.

BUG 1 - current_order NoneType on .upper():
  Root cause: record.get("BULK_TRACK_LAST_STATUS_CODE_DESCRIPTION", "")
    returns None when the key exists but has a None value. .upper() crashes.
  Fix: Changed to (record.get(...) or "").upper() null-coalescing pattern.
  File: packages/agents/shipments/skills/current_order/execute.py line 70

BUG 2 - shipment_delay_predictor missing shipments_result:
  Root cause: In cat-agents, a separate shipments_analysis_node (graph node)
    creates state["shipments_result"] before skills run. Our standalone
    pipeline has no such node, so the key never exists.
  Fix: Added _find_active_shipments() fallback function that checks:
    1. state[target_result_key].active_shipments (original cat-agents path)
    2. state["current_order_result"]["grounded_metrics"]["active_order_details"]
       (Phase 1 result injected between phases)
    3. state["shipment_data"]["records"] filtered for undelivered records
  Also returns a clean "no_active_shipments" result dict instead of None
    when all shipments are delivered.
  File: packages/agents/shipments/skills/shipment_delay_predictor/execute.py

RESULT: Both skills now complete successfully. current_order found 1 active
  order (tracking D10017134276666, OnTrac, shipped 2026-02-12).
  delay_predictor analyzed the active shipment via LLM and returned route
  performance data (MCO1->85142 at 33.3% delay rate vs PHX1->85142 at 0%).
  These were both broken in cat-agents for the same customer.

Entry 14: Skill Data Fallback Fixes (2026-02-13)
-------------------------------------------------
WHAT: Added data fallback chains across 7 skills to handle missing/null
     fields in S3 data. These fix silent misclassifications caused by
     SHIPMENT_WAS_DELAYED being None for all records, BULK_TRACK_DELIVERY_DTTM
     being None for delivered shipments, and weight field gaps.

WHY: Validation against raw S3 data for customer 6180005 revealed that
     skills were producing incorrect results due to data quality issues:
     - All 30 records had SHIPMENT_WAS_DELAYED=None, making delay detection
       fail silently (0% delay rate when actual was ~37%).
     - Shipment 500776879286 had BULK_TRACK_DELIVERY_DTTM=None but
       SHIPMENT_STATUS=DELIVERED, causing false "active" classification.
     - delivery_performance claimed "all delivered" while 2 records
       had no CTD (undelivered/in-transit).
     - exception_analysis type categorization showed "No Exception" for
       records flagged only via ONTIME_DELIVERY_FLAG=0.

HOW: Implemented fallback chains in each skill:

  1. current_order (execute.py):
     - Status: BULK_TRACK_LAST_STATUS_CODE_DESCRIPTION -> SHIPMENT_STATUS
       -> WIZMO_CURRENT_PKG_STATUS
     - Delivered check: BULK_TRACK_DELIVERY_DTTM not None -> SHIPMENT_STATUS
       == "DELIVERED" -> WIZMO_CURRENT_PKG_STATUS == "DELIVERED"
     - Expected delivery: EXPECTED_DELIVERY_DATE -> SHIPMENT_ESTIMATED_DELIVERY_DATE
       -> WIZMO_CURRENT_ARRIVAL_DATE -> LAST_EXPECTED_DELIVERY_DATE
     - Added _is_delivered() helper for consistent delivered count

  2. shipment_health_check (execute.py):
     - Delayed: SHIPMENT_WAS_DELAYED=True -> ONTIME_DELIVERY_FLAG=0
     - Delivered classification: BULK_TRACK_DELIVERY_DTTM -> SHIPMENT_STATUS
       -> WIZMO_CURRENT_PKG_STATUS (reports delivered/undelivered counts)
     - Updated delay_definition metadata

  3. package_analysis (execute.py):
     - Weight: BULK_TRACK_LB_PACKAGE_WEIGHT -> SHIPMENT_PLANNED_WEIGHT
       -> WAREHOUSE_SCALE_WEIGHT

  4. delivery_performance (execute.py):
     - Delayed: CTD > threshold -> SHIPMENT_WAS_DELAYED=True
       -> ONTIME_DELIVERY_FLAG=0
     - Reports delivered_with_ctd vs undelivered_count explicitly
     - No longer claims "all delivered" when undelivered records exist
     - Updated delay_definition metadata

  5. carrier_analysis (execute.py):
     - Delayed per carrier: same 3-way fallback as delivery_performance

  6. shipment_delay_predictor (execute.py):
     - _find_active_shipments() Source 3: added SHIPMENT_STATUS and
       WIZMO_CURRENT_PKG_STATUS fallbacks for delivered detection and
       status resolution

  7. exception_analysis (execute.py):
     - Added ONTIME_DELIVERY_FLAG=0 as exception signal
     - Added SHIPMENT_WAS_LOST=True check
     - Fixed exception type categorization: only uses exc_desc when
       has_exception is True; otherwise assigns descriptive type
       (Lost/Delayed/Not on-time)
     - Reports lost_shipment_count in grounded_metrics

RESULT (pipeline run for 6180005):

  - health_check: 11 delayed (36.7%) via ONTIME_DELIVERY_FLAG (was 0%)

Entry 15: CTD-Only Delay Detection (2026-02-13)
------------------------------------------------
WHAT: Removed ONTIME_DELIVERY_FLAG from all delay/exception detection.
     Delay is now purely CTD > threshold. Added estimated CTD fallback
     for records missing CLICK_TO_DELIVER_DAYS.

WHY: Validation against raw S3 data for customer 6180005 showed that
     ONTIME_DELIVERY_FLAG does not correlate with actual delivery timeliness.
     All 11 records with ONTIME_DELIVERY_FLAG=0 delivered ON or BEFORE
     their expected delivery date. The flag appears to measure something
     other than delivery vs estimated date (possibly an internal SLA we
     don't have visibility into). Using it inflated delay counts from 4
     to 11-14 with false positives.

HOW:
  1. shipment_health_check: Removed ONTIME_DELIVERY_FLAG fallback.
     Added _parse_date() helper. Added estimated CTD computation from
     SHIPMENT_ESTIMATED_DELIVERY_DATE / WIZMO_CURRENT_ARRIVAL_DATE /
     LAST_EXPECTED_DELIVERY_DATE - ORDER_PLACED_DTTM. Computes its own
     CTD threshold (mean + 1 std dev) for delay detection. Tracks
     estimated_ctd_count in grounded_metrics.

  2. delivery_performance: Removed ONTIME_DELIVERY_FLAG from delayed
     detection. Added _parse_date() + estimated CTD fallback. Now tracks
     actual_ctd_count, estimated_ctd_count, no_ctd_count. Flagged
     shipments include ctd_source ("actual" or "estimated").

  3. carrier_analysis: Removed ONTIME_DELIVERY_FLAG. Added _parse_date()
     + estimated CTD fallback. Delayed per carrier = CTD > threshold only.

  4. exception_analysis: Removed is_not_ontime and "Not on-time
     (ONTIME_DELIVERY_FLAG=0)" type. Exceptions now = actual carrier
     exceptions + SHIPMENT_WAS_DELAYED + SHIPMENT_WAS_LOST only.

RESULT (pipeline run for 6180005):
  - health_check: 4 delayed (13.3%), threshold 4.19 (incl 2 estimated CTDs)
  - delivery_performance: 4 delayed (13.3%), threshold 4.29
    Flagged: 494399793244 (CTD=5), 496272761367 (CTD=5),
             D10016935065020 (CTD=5), 476834403040 (CTD=7)
  - carrier_analysis: FedEx 3 delayed (16.7%), OnTrac 1 delayed (9.1%)
  - exception_analysis: 0 exceptions (0%)
  - 2 estimated CTDs computed (500776879286: ~1d, D10017134276666: ~2d)
  - All 30 records now have CTD coverage (28 actual + 2 estimated)
